# STATUS — `hmd-semantics`

`tools/hmd-semantics` — the builder of a vault's semantic index: a Python
command that reads a vault, embeds the text of each card with an embedding
model, and writes an SQLite file into the vault's `.hmd/`. A reader ranks cards
against a query from that file and runs no model. The tool also verifies an
index against its vault and prints what an index says about itself.

Beside this file: the format itself in [`lang.md`](lang.md), the canonical
implementation in [`hmd.md`](hmd.md), the TypeScript implementation in
[`ts-core.md`](ts-core.md), its editor in [`vsc-ext.md`](vsc-ext.md), the Rust
resolver crate in [`rs-core.md`](rs-core.md), and the website in
[`pages.md`](pages.md).

## Status

**Moved here from HQL with its behavior unchanged, and not published.** The
tool builds an index at one depth, the card itself, in schema version 1. It
embeds with a checkpoint in its own process or with a model behind an HTTP
endpoint, as the vault's `.hmd/config.toml` declares, and it embeds the queries
it is given, because a reader cannot. 79 tests, which need no model and no
network.

The two coarser depths, a one-paragraph and a one-sentence summary of each
card written by a language model, are specified and not built. Neither is the
schema version that carries them.

The tool is its own Python project with its own lockfile, outside the uv
workspace at the repository root, so that the model frameworks its `local`
provider needs stay out of the root lockfile. It is not on PyPI.

Its first reader is HQL's `hmd` package.

## Limitations (known gaps)

| Limitation | Why it stands | References |
| --- | --- | --- |
| The text contract is shared with HQL's loader, and a change to either must change both | The text this tool embeds and hashes has to be byte-identical to the text HQL hashes, so `vault.py` reimplements HQL's document loader and its frontmatter parser. Nothing in this repository runs HQL's loader, so a difference is caught only by HQL's own tests over its copy of the fixture vault | [[hmd-0028#the-embedded-text]] |
| Cards are loaded from the vault's root, not from the namespace root the `wiki` setting names, and `.md` and `.markdown` files are cards too | That is what HQL's loader loads and how it names cards, and an index whose card names differ from its reader's is an index of nothing. It moves when HQL's loader moves | [[hmd-0028#the-cards-of-an-index]] |
| The frontmatter parser is not a YAML parser | It is HQL's: block mappings, block and flow lists, and plain scalars. Frontmatter outside that subset is read as HQL reads it, which is the property that matters here | [[hmd-0028#the-embedded-text]] |
| An index answers only the queries it was built with | A reader has no model and cannot embed a question, so `build --query` embeds each one and a query the index does not hold is a failure at the reader | [[hmd-0028#schema-version-1]] |
| The committed fixture index names the tool's former name | It was built before the move and reads `hql-semantics 0.1.0`. Rebuilding needs the model, and no reader compares the string | [[hmd-0028#schema-version-1]] |
| The `local` provider is not exercised by a test | It needs `torch`, `transformers` and a checkpoint, which CI does not install. Its arithmetic is the pooling and normalising in `embed.py` | [[hmd-0028#the-embedder]] |
| `endpoint` and `api_key_env` are accepted and unused under `local` | The table is checked for what the chosen provider needs, and a key the provider does not use is left alone | [[hmd-0028#the-embedder]] |

## Done

- **`build`** — every card of a vault and every `--query` embedded and written
  as schema version 1, with the build stamp pinnable so a rebuild of an
  unchanged vault is byte-identical [[hmd-0028#schema-version-1]].
- **`verify`** — stale cards, cards missing from either side, vectors of the
  wrong length, and vectors that are not unit length, with exit status 1.
- **`inspect`** — what an index says about itself.
- **`[semantics]` and `[semantics.embedder]`** — the index path held inside the
  vault, the `local` and `http` providers, flags over the table key by key, and
  the refusals: an unknown key, an unknown provider, a literal `api_key`, an
  `http` embedder without `endpoint`, `model` or `revision`
  [[hmd-0028#the-semantics-table]].
- **The package** — the distribution `hypermarkdown-semantics`, the command
  `hmd-semantics`, no dependency, and `torch` and `transformers` as the extra
  `local`.
- **A CI job** — the tests against the tool's committed lockfile, with no model
  framework installed.
